# PHASE 2 STEP 3C — EVIDENCE CONTRACT

Status: contract for the additive `LearningEvidence` ledger. No adaptive recommendation or mastery logic is included.

## Purpose

`LearningEvidence` records what a student answered and what the server determined. It is separate from:

- `LearningSkill`: current cumulative skill reward/state;
- `PlayerActivity`: activity/reward timeline;
- XP, coins, streak, and leaderboard: reward systems;
- UKBI/TKA `TestAnswer`/`ProgresKompetensi`: certified assessment records.

## Canonical Record

| Field | Meaning | Rule |
|---|---|---|
| `id` | evidence row identity | generated by Prisma/server |
| `userId` | owner | always from authenticated server session |
| `source` | product flow | server constant such as `JALUR_CERDAS` or `LATIHAN` |
| `activityId` | containing activity/session | server identity: Jalur `unitId`, Latihan `QuizSubmission.id` |
| `questionId` | stable source question identity | supplied to the server only as a selector, resolved against server content; never question text/browser ID |
| `selectedAnswer` | answer submitted by student | stored after server validation; answer key is never stored here |
| `isCorrect` | server result | nullable for unanswered/not-evaluated records |
| `score` | server result score | nullable; Jalur uses `1`/`0`, Latihan uses points earned |
| `skill` | verified skill tag | nullable until question metadata is reviewed |
| `difficulty` | verified difficulty | nullable until source metadata is canonical |
| `answeredAt` | event time | server timestamp |
| `metadata` | version/source details | no client reward claims; versioned JSON only |
| `createdAt/updatedAt` | ledger timestamps | server-managed |

## Idempotency

Unique identity:

```text
(userId, source, activityId, questionId)
```

Jalur uses an upsert, so a retry updates the same evidence row. Latihan uses a submission-scoped batch replacement before marking the submission completed. This prevents duplicate evidence for a repeated request without treating question text as identity.

## Ownership

No request body `userId` is accepted. `userId` is derived from `getUser()` and used in the database write and read predicates.

## Server Result Rules

- Browser submits selected answers only.
- Server loads the answer key from `LearningUnit.content` or server-side `Soal` data.
- `isCorrect` and `score` are calculated server-side.
- Client-provided `isCorrect`, `score`, `skill`, and `difficulty` are not authoritative and are not persisted.

## Deliberate Non-Goals

- No mastery calculation.
- No automatic weak-skill detection.
- No difficulty adaptation.
- No mass metadata tagging.
- No UKBI/TKA migration into this ledger.
- No XP/coin/streak writes from the evidence helper.
